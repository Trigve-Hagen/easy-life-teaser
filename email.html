Phase 3: Email Account & Category Management Built

Documentation

Model email accounts and keyword-driven categories, then classify a message against them. Each category has a comma-separated keyword list and an action (auto_reply, flag, archive, forward); classification picks whichever category has the most keyword hits in the subject+body, or leaves the message unclassified if nothing matches — it never guesses. Every matched action (not just auto_reply) is staged and waits for an explicit approval before it's treated as done.

An account can optionally be connected to a real Gmail or Outlook mailbox via OAuth (PKCE, a local-loopback browser sign-in — no password is ever typed into LifeModel, and the resulting tokens live in your OS's secure credential store, never in the vault database). Once connected: Sync now pulls real messages into a local inbox cache and classifies each one automatically; approving a real message's staged classification actually replies (auto_reply) or files it into the folder/label set on its category (flag/archive/forward) — deletion always trashes, never permanently purges. A staged classification can also be turned into a calendar event proposal (date/time pulled from the message via a local AI model if one's configured, or a fallback pattern match otherwise); proposals stay as local drafts until you explicitly confirm one, which is the only action that pushes it to your real calendar.

Setup note: connecting a real account requires your own registered OAuth client — LifeModel can't create one on your behalf. Register a public/installed OAuth client (Google Cloud Console for Gmail, an Azure AD app registration for Outlook) and set GOOGLE_OAUTH_CLIENT_ID / MS_OAUTH_CLIENT_ID (and optionally MS_OAUTH_TENANT) as environment variables before starting the backend. Everything on this page still works against manually-typed test messages with no setup at all.

Tutorial

  1. Open the Email page, pick a profile, and click + New account — enter an email address and save.
  2. Add one or more Categories: a name, comma-separated keywords, an action, a reply template (for auto_reply) or a "file to" folder/label (for flag/archive/forward) using {{sender_name}}/{{subject}} placeholders where relevant.
  3. Optional: under Connection, click Connect Gmail or Connect Outlook — a browser tab opens for you to sign in and grant access; the page updates automatically once it completes. Click Sync now to pull real messages into the Inbox list below.
  4. Under Test classification, paste in a from/subject/body and click Classify to see which category matches without touching real mail.
  5. Check the Classification log — anything staged needs an explicit Approve click. On a connected account, approving a real synced message's entry actually acts on it; the log tags each entry "real message" or "test" so it's always clear which is which.
  6. Click Propose calendar event on a staged entry to draft a Calendar proposal below — review it, then Confirm & push (connected accounts only) or Discard.

Email Template Modules (Step 359) Built

The same content-package marketplace shape Steps 315–317 already built for Marketing Plan Modules, reused rather than reinvented: a well-crafted set of categories (a "customer support triage" pack, a "recruiter screening" pack) can be built once and listed for anyone else to install instead of hand-writing rules from scratch. No module_type split the way marketing plans need (plain vs. video) — an email-template pack is text-only, so storage_type alone (a small hosted JSON bundle, or a pointer to the seller's own GitHub repo for a larger pack) is the only "where does this live" question. The manifest is a plain JSON array of {category_name, match_rules, action_type, reply_template} objects — the real shape EmailCategory already stores (a flat, comma-separated keyword string checked against subject+body, per Step 7), not a richer field this app has nowhere else to read.

On gwm_site's Modules page's Email Templates tab, a signed-in seller uploads either shape and approves their own pending listings from Mine (now spanning both Marketing Plan and Email Template listings in one combined queue). Back here in the Email page's Template modules section, every listed module shows up with the same three explicit WordPress-style actions as Marketing Plan Modules: Download/Install both fetch the module's real current content (a direct download for a hosted bundle, a real read-only git clone for a GitHub one) and show exactly what's inside — every category name and its action — before anything is written. Enable always re-fetches fresh and creates the real EmailCategory rows on the account you're viewing, skipping (never overwriting) any category whose name already exists there, the same idempotency rule Step 353's job-category seeding already uses — and reports any skip by name, not just a count, so a smaller-than-expected install is always explainable.

Tutorial

  1. On the Email page, select the account with the categories you want to package, and click Export categories for a module in the Categories section — this downloads a real categories.json built from your own working categories.
  2. On gwm_site's Modules page, sign in, open the Email Templates tab, and upload that file (or paste a repo URL/commit if you pushed it to your own GitHub repo instead).
  3. On the Mine tab, click Approve on your new listing so it becomes publicly listed.
  4. Back on the Email page's Template modules section, click Refresh and find your listing.
  5. Click Download or Install — either fetches the real content and shows every category name and action it contains.
  6. Click Enable — confirm the real new categories now exist in the Categories section above, and that installing the same module again correctly skips them as already present.
