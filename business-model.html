Phase 15: Business Model — Financials, Marketing & Document Generation Built

Documentation

Competitor tracking: you add each competitor you actually want tracked — competitor_research.py never expands that list on its own, it only researches names already on it. Click Research to run a real public web search (reusing the same DuckDuckGo-HTML search Phase 8's lender research already uses — no login-gated content, no bypassing a site's terms) and log new CompetitorObservations, each carrying its source link. You can also log an observation by hand any time.

Financial statements: every entry in the BusinessLedgerEntries log is one real transaction or balance movement — revenue, COGS, opex, an asset/liability/equity balance, or a cash-flow line. financial_statements.py is pure math with no database access of its own (same split as Phase 8's finance_utils.py), unit-tested against hand-computed examples: an income statement and cash flow statement filter to a period (a month or a whole year), while the balance sheet sums everything up to an as-of date, since assets/liabilities/equity are point-in-time balances, not period flows. A balance sheet that doesn't actually balance reports balanced: false loudly rather than hiding the problem.

Invoices & proposals: add a client, then an invoice with line items — subtotal and total are computed and stored the moment you save it. Render PDF produces a real downloadable document (reusing the same Playwright HTML-to-PDF rendering Phase 4's resume builder already established) — nothing is ever emailed automatically, it's a file for you to review and send yourself. Marking an invoice paid doesn't touch the ledger by itself; Record as revenue is a separate, explicit click that adds the matching BusinessLedgerEntries row, so nothing ever gets double-booked silently. Proposals work the same way, minus the ledger link.

The rollup agent: the summary at the top of the page ties the current period's financials, open invoices/proposals, active marketing-plan elements (Phase 11), and recent competitor observations into one view. Ask it a plain-language question — "are we profitable this quarter?", "what's our largest open invoice?", "how does our pricing compare to <competitor>?" — and it answers by querying that same real data and citing the figures it used, same "cite the numbers, don't guess" rule as Phase 8's budget Q&A and Phase 11's marketing budget suggestions. A question it doesn't have a rule for says so honestly instead of guessing at intent.

Financial app sync (Steps 214/216): connect QuickBooks Online, Xero, Wave, FreshBooks, or Plaid on the Financial app sync panel — the OAuth token goes straight into the OS keyring via credential_store.py (the same generic pattern Phase 3's email OAuth established), never into personal_vault.db. Preview sync is read-only: it fetches from the provider and shows real fetched/new/duplicate counts and totals without writing anything. Confirm sync never trusts that preview — it independently re-fetches fresh from the provider and re-computes before writing, so a stale or tampered preview can never force a bad import. Duplicates are caught by each provider's own record id (external_provider + external_ref, a unique constraint on the ledger and invoices tables), not guesswork. Every connector fails closed: no real account connected means an honest empty result, never a fabricated fetch.

Selective data groups & JSON import/export (Steps 215/217): financial data is split into five groups — revenue, expenses, assets/liabilities, invoices/clients, competitors — mirroring the same curated-category shape Phase 10's data-access grants already use. Pick any combination on the Import/export panel to export just those groups as JSON, or paste JSON back in to import. Hand-authored or re-imported rows have no provider record id, so duplicate detection there hashes each row's real content (date, category, account, amount) instead — re-importing the exact same export always reports zero new records.

Industry-tailored marketing plans & campaign actions (Steps 224-227): generating a plan with no channels typed in tailors the channel list to the company's industry field (consulting/agency, retail/e-commerce, restaurant/local each get a different real channel set — a small hand-curated lookup, never an LLM improvising strategy) and proposes a linked campaign action for channels that map to one: email nurture → an email campaign, local SEO/blog channels → a blog post, paid social → an ad campaign. Every campaign action defaults to suggest_only — the "Actions" panel on each plan element (Marketing page) requires an explicit click to draft or send/publish/post, same as every other consequential action in this app. Enable auto-run is a separate, explicit opt-in per action, and Disable is an instant kill switch. Email sends only reach non-unsubscribed leads and always include an unsubscribe line (Phase 16 Step 57's CAN-SPAM rule applies here too); blog publishing and ad posting are real HTTP calls that report an honest failure — post stays a draft — when no working site/platform credential is connected, never a fabricated success.

Tutorial

  1. Open the Business Model page, pick a profile, and pick (or create on the Marketing page) a company.
  2. Under Competitors, add one you actually want to track, then click Research — review what it found under Observations, each with its source link.
  3. Under Financials, add a few ledger entries (a revenue row, an opex row, an asset/equity pair for an opening balance) and watch the income statement, balance sheet, and cash flow figures update — try a period like the current month.
  4. Add a Client, then an Invoice with a couple of line items — check the computed subtotal/total. Click Render PDF, then mark it paid and click Record as revenue — watch the ledger and the rollup's net income change.
  5. Add a Proposal and render it too.
  6. Scroll to the top and ask the rollup agent a question — "are we profitable this quarter?" or "what's our largest open invoice?" — and check that its answer matches the real numbers on the page.
  7. Under Financial app sync, add a connection for one of the five providers, click Preview sync, then check a couple of data groups and click Export — paste the resulting JSON straight back into Import and confirm it reports zero new records.
  8. Go to the Marketing page, set an industry on the company, and generate a plan with no channels typed in — check the channel titles match the industry, open Actions on a channel that got a linked action, and draft its email template / blog post / ad.
