Phase 21: Personal Preferences, Gift-Giving & Reminder Agent Built

Documentation

Two halves that share one idea — asking structured questions about what someone likes instead of guessing. The first half turns that toward you (sharper job-search matching); the second turns it toward the people in your life (gifts that land, sent on time), both on the new Gifts & Relationships page and the job-search side of Goals.

Job-search preferences (Step 135): the same guided-intake pattern as Phase 17's life values, extended with a job-search-specific question set — industries you like or would rule out, preferred work environment, remote/hybrid/onsite, team size, management style, dealbreakers. These are stored as LifeValues rows tagged context = job_search, so GET /life-values?context=job_search reads just this set without touching Phase 17's general happiness intake. When you go to search Indeed, GET /profile/{id}/indeed-search-criteria/suggested pre-fills keywords and a remote-only guess from these answers — a suggestion you still review and submit yourself, never an auto-applied override; the response also names exactly which recorded preference fed each field.

Contacts & preferences (Step 136): a Contact is who you might buy a gift for — name, relationship, birthday, anniversary, notes. Click Guided intake under a contact to answer a fixed set of prompts about them (what they collect or enjoy, clothing sizes, favorite colors, favorite brands or stores, and — the important one — anything to avoid: allergies, dietary restrictions, things they've said they don't want). Each non-blank answer becomes its own structured, categorized row, same "no freeform blob" discipline as every other guided intake in this project.

Occasion reminders (Step 137): add a GiftOccasion (birthday, anniversary, holiday, or custom) with a reminder lead time in days. Check reminders now runs gift_reminder_job.process_reminders for real — it flips upcoming to reminded once today crosses occasion_date - reminder_lead_days, and rolls a recurring occasion's date forward exactly one year once it's marked handled (with a Feb 29 fallback to Feb 28). There's no OS-level scheduler wired into this desktop app yet, so this is a manual trigger today — the same honest gap as every other "runs on a schedule" step in this plan; a cron/launchd entry would call the same endpoint.

Gift suggestion agent (Step 138): click Get new suggestions and gift_suggestion_agent.py reads only that contact's recorded preferences and drafts ideas — a preference tagged avoid is a hard exclusion, it is never a source for a suggestion, and every idea states exactly which preference row it matched. Check Include public web search results to also pull real gift-idea search results (reusing the same DuckDuckGo-HTML search Phase 15/17 already use — public pages only) with a real source link on each; leave it unchecked for offline, heuristic-only ideas. Every suggestion starts at suggested — picking one is always your own click.

Automated ordering (Step 139) — the strictest guardrails in this phase, because it's the only step that spends real money: an Auto-order rule is always created suggest_only regardless of what you set on the form; switching it to auto-order is a separate, explicit action behind a confirm dialog warning that real money will be spent, up to the stated cap, with no further per-order confirmation. Disable auto-order is an instant kill switch. Attempt now runs gift_ordering_agent.attempt_auto_order for real — it only ever picks a suggestion with a real recorded price at or under the rule's cap and inside its category allowlist.

Honest gap: this backend has no live gift/flower provider API integration — Stripe lives only in product_backend/ (Phase 13), not here. attempt_auto_order never places a real charge or fabricates an order confirmation; it reports exactly what it would do once a real provider is wired in ("selection succeeded but no real order was placed") instead of pretending success. Because of this, most drafted suggestions also carry no estimated_price, so most auto-order rules will honestly report "no suggestion within cap" until real pricing data exists. Order this on a suggestion is a manual log, not a checkout — you place the order yourself through whatever real storefront it points at, then record what you actually paid. See CLAUDE_PLAN.md's "Known Limitations" section for the current full list.

Tutorial

  1. On Goals, open Life values and try the job-search side of the guided intake (industries liked, remote preference, dealbreakers), then check that GET /life-values?context=job_search and the Indeed search-criteria suggestion both reflect it.
  2. Open Gifts & Relationships and add a contact, including a birthday.
  3. Click Manage, run the Guided intake, and make sure to answer the "anything to avoid" prompt with something real.
  4. Add a Gift occasion dated within your reminder lead window, then click Check reminders now at the top of the page and watch its status flip to reminded.
  5. Click Get new suggestions and confirm every idea returned names the preference it matched, and that nothing drawn from the "avoid" answer appears.
  6. Add an Auto-order rule, click Attempt now, and read the honest result — it should say no live provider exists yet rather than claim an order happened.

Next steps

  • Wire a real gift/flower ordering provider API into gift_ordering_agent.py so attempt_auto_order can place a real order instead of reporting the honest gap.
  • Have the gift suggestion agent estimate real prices (from web search results or a provider catalog) so auto-order rules have something to actually match against.
  • Wire an OS-level scheduler (cron/launchd) to call POST /gift-occasions/process-reminders automatically instead of the manual button.
  • Surface the job-search preference panel directly on the Job Search page (Step 62) as an optional "tell us what you're looking for" panel, per the original Step 135 plan text.
