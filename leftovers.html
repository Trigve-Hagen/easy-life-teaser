Phase 5: Filesystem Path Registry & Cleanup Built

Documentation

Three registries: protected paths that must never be touched, junk paths that accumulate disposable files (a folder, a glob pattern like *.tmp, a max age in days, and how often to check), and notes paths (pure organizational metadata — no automation reads these). None of this is tied to a profile; it describes the machine, not a person.

A dry-run scans a junk path fresh every time and reports exactly what it would remove — it never deletes anything. Confirm deletion re-scans (never reuses a stale list) and actually removes matches, but only after every candidate is cross-checked against every protected path first: if even one match falls under a protected path, the entire run is blocked and nothing is deleted at all — not even the files that had no conflict. Every run, dry or confirmed, is logged in the run history below with what matched, what was removed, and bytes freed.

A cron job runs the dry-run scan daily (see backend/scripts/run_cleanup_dryrun.py and crontab -l) for whichever junk paths are due per their own cleanup_frequency — the schedule only ever triggers a dry-run report; actual deletion is always a direct, explicit click on this page.

Software leftovers: the Software leftovers page knows what came with the OS (a seeded baseline per target — WSL2 and Windows) and can do a real read of what's actually installed right now (dpkg-query on WSL2, the same registry hives Windows' own "Apps & Features" panel reads on Windows). A folder under /opt, /usr/local, Program Files, or similar only gets flagged when it's outside that baseline and nothing currently installed owns it — every flagged item states that exact reason. This is a heuristic, not a certainty, so there's no auto-delete mode at all: every deletion is reviewed and confirmed one at a time, and anything under a protected path is skipped and shown as blocked.

Move to external drive: the Move to external drive page is for real, wanted files (old photos, finished projects) rather than junk. Register a drive and a folder to watch, and it suggests files that are both large and old — a recent large file or a small old one is left alone. Confirming a move copies the file to the drive first, verifies the copy against the original by size and a streamed content hash (Step 211 — a copy that's the right size but silently corrupted, from a flaky drive or a dropped connection, is caught before the original is ever removed), and only then deletes the source. No auto-move mode here either; every move is its own explicit click.

Safety hardening (Steps 209–213), added once these features became a free, widely-downloadable tier (Phase 13): a confirmed cleanup or leftover deletion never disappears immediately — it moves into a 14-day quarantine (Step 209) with a Restore button right on the page it was deleted from; only a scheduled job (scripts/run_quarantine_purge.py) makes it permanent, and only once that window passes. Protected paths now seeds real OS-critical defaults on first run (Step 210) — /etc, /usr, C:\Windows, C:\Program Files, and this app's own data directory — marked distinctly from anything you add yourself, so a free-tier install has real built-in protection even if you never visit that page. Every dry-run/scan now returns an opaque scan token (Step 212) that the matching confirm action must present back — a cleanup confirm literally only ever acts on the exact file list from one specific, still-fresh (30-minute) dry-run, never an independent rescan that could sweep up a file you were never shown; the leftover and move-suggestion queues use the same token to prove a confirm click is actually backed by the current proposal, with no time limit since those are meant to be reviewed at leisure. Finally, every page here shows a banner if the app is running with elevated (root/Administrator) privileges (Step 213, informational only), and the real-write confirm endpoints are rate-limited so a runaway script fails fast instead of deleting at machine speed.

Tutorial

  1. Open the Filesystem page.
  2. Under Protected paths, notice the paths already seeded and marked "seeded — OS-critical" — add anything else that must never be touched, like your own repo or a config directory.
  3. Under Junk paths, add a folder + glob pattern (e.g. *.tmp or node_modules) + max age + how often to check.
  4. Click Run dry-run and review the reported matches and freed-space estimate in the Cleanup run log below before doing anything else.
  5. If it looks right, click Confirm deletion within the next 30 minutes — you'll be asked to confirm once more before anything real happens. If any match overlaps a protected path, you'll see "Blocked" and nothing is deleted; otherwise, matches move into the Recently deleted panel, restorable for 14 days.
  6. Notes paths is just a reference map (category name → folder) — informational only.
  7. Open the Software leftovers page, click Refresh under Installed software for your target, then Scan under the leftover queue. Review each candidate's reason before clicking Confirm delete (also lands in that page's own Recently deleted panel) or Dismiss.
  8. Open the Move to external drive page, register a drive and a folder to watch, then click Scan watched folders. Pick a drive with enough free space shown and click Move, or Dismiss a suggestion you'd rather keep in place — the move log shows the verified content hash once it completes.
