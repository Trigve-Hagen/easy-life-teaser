Phase 6: System & WSL2 Maintenance — Preview

Documentation

Keeps three things patched: WSL2's Linux packages (apt), the WSL2 kernel itself, and Windows. A check is always read-only — it reads the existing apt package cache, asks wsl.exe --status, or (via a PSWindowsUpdate PowerShell check on the Windows side) lists pending Windows updates — and never changes anything on its own. Confirm & apply is the one real, system-wide action: it actually installs updates, and it's only ever reachable through that direct click on the System Maintenance page, never from a schedule. Every check and apply, whichever target, is logged with its outcome.

A scheduled cron/task entry (backend/scripts/run_update_dryrun.py — not installed automatically) can run the dry-run checks on a regular cadence so the history stays current even if you don't visit the page; it only ever calls the read-only checks, never applies anything.

Tutorial

  1. Open the System Maintenance page (under Clean your computer in the side menu).
  2. Click Check for updates under any target — this only reads current state, nothing changes yet.
  3. Review the summary and status shown, and the entry it adds to the Update history log below.
  4. If you actually want to install what was found, click Confirm & apply — you'll be asked to confirm once more before anything real happens on your machine.
